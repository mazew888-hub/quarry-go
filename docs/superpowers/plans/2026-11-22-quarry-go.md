# Quarry Go Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the approved "Vista review test" player into Quarry Go: an installable iPhone home-screen web app with a saved reviews list. Each review keeps a copy of its clip and its notes, marks, loop, retimes and rate.

**Architecture:** A static site with no build step: plain ES modules, served from GitHub Pages. Pure logic (retime timeline, GIF decoding) lives in small modules tested with Node's built-in test runner. Browser behaviour (storage, player, offline) is tested with Playwright driving the installed Chrome. The player is a port of the spike, not a rewrite.

**Tech Stack:** HTML/CSS/JS modules, IndexedDB, Service Worker, MediaRecorder, `node --test`, Playwright (Python) with `/usr/bin/google-chrome`.

**Spec:** `docs/superpowers/specs/2026-11-22-quarry-go-design.md` (a copy of the approved doc https://claude.ai/artifact/3mkDTEeS6iLdPdSXWqKuMa)

**Source to port:** `/home/claude/spike/index.html` (the artifact "Vista review test", version 1795389314-005a). Every player behaviour listed in the spec's Goals is already in it, with tests in `/home/claude/spike/t7.py`–`t9.py`.

## Global Constraints

- **Name:** the app's name is "Quarry Go" and the repo is `quarry-go` (public, code only; never commit media).
- **Network:** no network requests after the first load. Fonts and every asset ship in the repo. No analytics and no CDNs.
- **No dependencies at runtime:** no npm packages ship; tests may use only what's installed (Node 22, Python Playwright, Chrome).
- **Look:** the planner A2 dark tokens, exactly as in the spike's `:root` (page `#1D2024`, board `#282C31`, surf `#31363D`, well `#212429`, accent `#4A7590`, light `#86B0C2`, coral `#E8908C`); glass keys on the video.
- **Frame cache:** at most 960px wide, and refused when `count*W*H*4 > 900e6`.
- **Saving:** every change saves immediately, and a pending save flushes on `visibilitychange` → hidden.
- **Tab bar:** hidden while Review is the only tab.
- **Icon:** show one sample icon to the user for approval before wiring it into the manifest.
- **Copy:** sentence case, plain words, matching the spike's tone.

## Review Focus

1. **The app is closed or killed straight after an edit.** Expected: the edit is there on reopen. Test: Task 5, `test_edit_survives_immediate_reload`.
2. **The phone's storage is full when a clip is copied in.** Expected: the message "Not enough space on this phone for that clip", and no half-made review in the list. Test: Task 3, `quota error leaves no review`.
3. **A clip that won't decode** (an unsupported codec or a broken file). Expected: the message "This clip can't be opened here", you're back on Reviews, and no review is saved. Test: Task 5, `test_bad_clip_makes_no_review`.
4. **A clip too long to hold in memory.** Expected: it's refused before anything is saved, with the spike's "too long" message. Test: Task 4, `test_too_long_refused_before_save`.
5. **A review whose stored clip is gone** (storage cleared by iOS). Expected: the notes are kept, and the player shows "The clip for this review is missing. Pick it again." with a picker that re-attaches the clip. Test: Task 5, `test_missing_clip_repick`.

### Task 2: GIF decoding

**Files:**
- Create: `js/gif.js`, `tests/gif.test.mjs`, `tests/fixtures/make_gifs.py`, `tests/fixtures/*.gif`

**Interfaces:**
- Produces: `decodeGif(buf:ArrayBuffer) -> {width:int, height:int, frames:{rgba:Uint8ClampedArray, delayMs:int}[]}`. Each frame is full-canvas RGBA after disposal is applied (methods 0–3) and transparency is composited. A delay of 0 or under 20 is treated as 100ms (browser convention).
- Produces: `gifTimeline(delays:int[]) -> {fps:number, slots:int[]}`. fps is `round(1000/minDelay)` clamped to 1..60, and `slots[i]` is how many timeline frames GIF frame i fills (min 1).

- [ ] **Step 1: Write `make_gifs.py`** using PIL to make three fixtures:
  - `solid3.gif`: 3 frames, 8×6, red/green/blue, 100ms each.
  - `mixed.gif`: delays 40, 120, 0.
  - `dispose.gif`: frame 2 is a 2×2 patch on transparent with disposal 2.

  Run it.
- [ ] **Step 2: Write the failing tests:**
  - `solid3` decodes to 3 frames, 8×6, and frame 1's pixel 0 is `[0,255,0,255]`.
  - `mixed` delays are `[40,120,100]`, and `gifTimeline([40,120,100])` is `{fps:25, slots:[1,3,3]}` (round(120/40)=3, round(100/40)=3).
  - `dispose` frame 3 shows the background where frame 2's patch was disposed.
  - A truncated buffer throws an `Error` whose message starts "This GIF".
- [ ] **Step 3: Run** `node --test tests/gif.test.mjs` and expect FAIL.
- [ ] **Step 4: Implement `decodeGif` and `gifTimeline`.** Parse the header, global and local colour tables, the graphic control extension (delay, disposal, transparent index), interlacing and LZW. This is a standard GIF89a decoder; keep it in one file under about 250 lines.
- [ ] **Step 5: Run** the tests and expect a pass, then commit with `feat: gif decoder`.

### Task 3: Storage

**Files:**
- Create: `js/store.js`, `tests/e2e/serve.py`, `tests/e2e/test_store.py`, `tests/e2e/store_harness.html`

**Interfaces:**
- Produces: `Review = {id:string, name:string, created:number, updated:number, fps:number, frameCount:int, width:int, height:int, thumb:Blob|null, marks:Mark[], secs:Section[], retimed:bool, inF:int|null, outF:int|null, rate:number, pos:int, clipType:string}`. `Mark` is the spike's mark object.
- Produces (all async; DB name `quarry-go`, stores `reviews` and `clips` keyed by review id):
  - `createReview(meta:Partial<Review>, clip:Blob) -> Review`. Writes both stores in one transaction. On a `QuotaExceededError` it throws `Error('Not enough space on this phone for that clip')` and leaves nothing behind.
  - `listReviews() -> Review[]`, newest `updated` first.
  - `getReview(id) -> Review|null`, `getClip(id) -> Blob|null`, `putClip(id, blob)`
  - `saveReview(id, patch:Partial<Review>)`: debounced 300ms per id, and it sets `updated`.
  - `flush() -> Promise`: writes pending saves now.
  - `deleteReview(id)`: removes both.
  - `deleteAll()`
  - `usage() -> {bytes:int}`: the sum of clip sizes.
- Produces: `serve.py` serves the repo root on `http://localhost:8765`, which is needed because modules and service workers don't load from `file://`.

- [ ] **Step 1: Write the failing tests** in `test_store.py`. The harness page imports `store.js` and exposes it on `window.S`; tests call it via `page.evaluate`.
  - `create then list`: one review, and its clip comes back with the same size.
  - `saveReview then flush then reload`: after a page reload, `getReview` has the new `marks`.
  - `quota error leaves no review`: stub `IDBObjectStore.prototype.put` to throw a `DOMException('', 'QuotaExceededError')` for the clips store. `createReview` rejects with the space message and `listReviews()` is empty.
  - `delete removes clip`: `getClip` returns null afterwards.
- [ ] **Step 2: Run** `python3 -m pytest tests/e2e/test_store.py` and expect FAIL.
- [ ] **Step 3: Implement `js/store.js`** with raw IndexedDB and a small promise wrapper.
- [ ] **Step 4: Run** the tests and expect a pass, then commit with `feat: review storage`.

### Task 4: The player as a module

- Port from: `/home/claude/spike/index.html`

**Interfaces:**
- Consumes: Task 1 (retime), Task 2 (gif).
- Produces:
  - `loadFrames(blob:Blob, {onFrame(i), signal}) -> {fps, count, W, H, frames:(ImageBitmap|null)[], done:Promise}`. Videos use the spike's two-pass loader (play-through with `requestVideoFrameCallback`, then seek the gaps). GIFs go through `decodeGif`/`gifTimeline`, which expands slots so repeated slots share one ImageBitmap. It throws the spike's "too long" message before decoding if over the memory limit, and `Error("This clip can't be opened here")` when it can't decode.
  - `openPlayer(root:HTMLElement, {blob, review:Review|null, onChange(patch:Partial<Review>), onBack()}) -> {close()}`. It restores marks, secs, retimed, inF/outF, rate and pos from the review, and calls `onChange` after every edit with only the changed fields.
  - `exportVideo(kind:'notes'|'retimed'|'both', ctx)`: the spike's export. The save order is the `claude.use('downloads')` capability when present (testing inside Claude), then `navigator.share({files})`, then an anchor download.
